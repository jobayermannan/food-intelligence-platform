# Food Intelligence Platform — upgrade guide

Backend 2.0 is implemented in `apps/api`; the legacy prototype remains in `legacy/`. The rename to `food-intelligence-platform` has been performed for the GitHub repository and active local checkout. No MongoDB production data was migrated. This guide covers future changes to the new PostgreSQL API, not an automatic conversion of legacy accounts or carts.

Before an upgrade, record the current Git revision, API image/build, migration version, environment keys, database backup and restore procedure, and expected clients. Run `npm ci`, lint, typecheck, migrations and PostgreSQL-backed tests against an isolated database. Review generated SQL for destructive operations, lock duration, composite FK/index ordering and backfill needs. Take a verified backup before migrating persistent data; test a restore on a separate database. Apply additive schema first where possible, then deploy compatible API code, monitor readiness/error rates and reconcile stock movement totals. Never assume a database downgrade is safe after live writes; restore/replay plans must be rehearsed.

For API changes, publish a versioned contract and coordinate actual clients. Do not retain insecure legacy JWT issuance, open admin routes, arbitrary roles, or unauthenticated cart access for compatibility. Current session security uses hashed rotating refresh tokens, revocation checks and Origin protection; rotate compromised credentials immediately. Production rollout also needs HTTPS secure cookies, a real mail provider, shared rate limiting for multiple instances, database operations/backup ownership, and verified Docker image deployment.

For a future legacy data import, follow [MIGRATION_PLAN.md](MIGRATION_PLAN.md): immutable MongoDB export, explicit transformation/ownership mapping, validation, reconciliation, then PostgreSQL import. Do not delete MongoDB or infer missing purchase/sale history. Deferred frontend, Astro runtime, payments, ML, queues and realtime each require their own upgrade and rollback plans when implemented.
