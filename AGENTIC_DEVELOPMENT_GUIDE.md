# Food Intelligence Platform — agentic development guide

Read [PRODUCT_DOMAIN.md](PRODUCT_DOMAIN.md) first, then [CODEBASE_MAP.md](CODEBASE_MAP.md), [DATABASE_DESIGN.md](DATABASE_DESIGN.md), and the actual source under `apps/api`. Phase 0 documents may describe deferred architecture; never treat them as proof that a feature exists. `legacy/index.js` is reference only, with known security defects.

For changes to protected endpoints, preserve active-user/session checks, business membership checks, and staff/viewer location grants. Tenant IDs from routes are inputs to verify, never authority. For stock/sale/return/waste changes, preserve exact Decimal arithmetic, nonnegative constraints, deterministic lock ordering, operation-key behavior, movement traceability, and all-or-nothing transactions. Do not use binary floating point for authoritative money or quantity. Keep Astro documentation-only and avoid importing API secrets or database modules into it.

Review generated Drizzle SQL before applying migrations; PostgreSQL composite foreign keys require their target unique indexes first. Run migrations and integration tests on an isolated `_test` database. Report actual lint/typecheck/test/build results, failed checks, and deployment caveats. Update canonical docs when behavior changes. Keep future payments, forecasting, Redis/BullMQ, Socket.IO, carts/reviews and frontend outside the MVP unless separately requested.
